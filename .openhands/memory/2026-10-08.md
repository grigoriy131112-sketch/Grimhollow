## "Site falls over on chat reload" вАФ root cause + fix
- Root cause of BOTH symptoms (the earlier "–Њ—И–Є–±–Ї–∞ –љ–∞ —Б–∞–є—В–µ" and this one):
  `client/dist` is gitignored, and `serve.sh` only built the client when
  `dist/index.html` was **missing**. After a sandbox pause/resume the volume keeps
  an old bundle, so the server serves stale JS with a live API. The site "falls"
  even though nothing in the source is broken.
- Fix in `scripts/serve.sh`: the built bundle is stamped with
  `git rev-parse HEAD:client` into `client/dist/.build-stamp`; `needs_build()`
  rebuilds when the stamp != HEAD:client, the stamp is missing, or a client
  source file is newer than `dist/index.html`. `build_client()` only stamps a
  build that produced an index (failed builds retry). `ensure()` and the resident
  `--watch` loop both call it, so a bundle that goes stale under a *surviving*
  server is rebuilt too. Verified: overwrote the stamp, watcher rebuilt within
  ~10s and restarted; both ports 200.
- **Hard limit (documented in AGENTS.md):** pause/resume wipes the resident
  watcher. Nothing in-sandbox survives. The only automatic recovery is the
  `session_start`/`user_prompt_submit` hook, which is frozen at conversation
  creation вАФ so it fires for conversations created after `.openhands/hooks.json`
  existed, not for pre-existing ones. There is no SDK resume hook (SDK hooks: only
  PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionStart, SessionEnd). So
  "never drops on reload" can't be guaranteed from inside the sandbox; for an old
  conversation the preview stays down until someone runs
  `bash scripts/serve.sh --watch`. This conversation *does* have the hook in its
  `meta.json#hook_config`, so it recovers on the next user message.
